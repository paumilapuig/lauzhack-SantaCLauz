# Spec: api-clips (owner A, branch `feat/api-clips`)

## Goal
`POST /api/clips` (API.md line 70) stores a student's 30 s webm in the private bucket `clips` at `{student_id}/{clip_id}.webm`, inserts the `clips` row and a `class_events` row of type `unclear` at `t_end`, and returns `{clip_id, audio_path}`. A helper `signed_clip_url` gives 1 h signed URLs for /home.
Acceptance: `cd api && uv run pytest` is green with 200/401/403/404/413/415/422/500-cleanup cases on a fake Supabase (tables + in-memory storage). Demo: on /class, "te la vas perdre" uploads a clip, and /home can play it from a signed URL.

## Contract changes
None. `docs/API.md` is not modified. No DB migration. No new library (`python-multipart` comes with `fastapi[standard]`; `storage3` comes with supabase-py 2.34.1). No remote Supabase operation.

## Decisions not in API.md
1. **Layout:** `api/app/routers/clips.py` (router), `clips_validation.py` (MIME + capped read), `api/app/storage.py` (shared bucket calls, moved out of `routers/`), `clips_repository.py` (`clips` row). Response model `ClipCreated{clip_id: str, audio_path: str}` goes in `classdata_schemas.py`. Laura confirmed these files are owner A's (CLAUDE.md ownership table updated).
2. **Form fields:** `audio: UploadFile`, `session_id: UUID`, `t_start: float` (>= 0, finite), `t_end: float` (> 0, finite), `transcript: str` (default `""`, max 5000 chars). A schema failure gives FastAPI's default list `detail` (422). If `t_end <= t_start`: `422 "t_end must be greater than t_start"`.
3. **Check order** (each check fails before the next one runs): 401 token, 403 role, 422 fields, 415 MIME, 413 size, 422 empty, 404 session. Then upload, then DB writes. Nothing is uploaded or written when any check fails.
4. **MIME:** base type = `content_type.split(";")[0].strip().lower()`. Only `audio/webm` is accepted, so `audio/webm;codecs=opus` passes. A missing or other type gives `415 "Audio must be audio/webm"`.
5. **Size:** `MAX_AUDIO_BYTES = 2 * 1024 * 1024`. Read `upload.file.read(MAX_AUDIO_BYTES + 1)`, never an unbounded `read()`. A longer read gives `413 "Audio larger than 2 MB"`. Exactly 2 MB is accepted. Starlette spools large parts to disk, so memory stays bounded. A 0-byte file gives `422 "Empty audio"` (the type is correct, the content is invalid).
6. **Ownership:** use `classdata_session_repository.get_owned_session(db, str(session_id), user.id)`. If it returns None: `404 "Session not found"` (unknown or foreign session).
7. **Upload:** `clip_id = uuid4()` (generated by the API). Path `clip_object_path(student_id, clip_id) = f"{student_id}/{clip_id}.webm"`. Call `db.storage.from_("clips").upload(path, data, {"content-type": "audio/webm", "upsert": "false"})`. If the upload raises: `500 "Could not store audio"`, and no DB row is written.
8. **Persistence order (A decision):** upload → `insert_clip(...)` (`id=clip_id`, `session_id`, `student_id`, `t_start`, `t_end`, `transcript`, `audio_path`) → `insert_event(db, session_id, user.id, t_end, "unclear", None)`. If the clip insert raises: `remove_clip(db, path)`. If the event insert raises: `delete_clip(db, clip_id)` then `remove_clip(db, path)`. Each rollback step is best-effort and independent (one failing does not skip the other; each logs its own error). Then `500 "Could not save clip"` from the original error. No orphan event is left: the event is last, and a single-row insert is atomic. No schema change is needed (service_role has `grant all` on `clips`; `clips.id` is supplied by the API, so the row is deleted by id).
9. **Signed URLs:** `signed_clip_url(db, path, expires=3600) -> str` returns `create_signed_url(path, expires)["signedURL"]` and does not catch errors. Never call `get_public_url`. The response returns `audio_path` only, never a URL.

## Tasks
### T1 — fake storage · **Files:** `api/tests/fake_storage.py` (new), `api/tests/fake_supabase.py` (+`self.storage = FakeStorage()`, +`"clips": "created_at"` in `_TABLES_WITH_TIMESTAMP`), `api/tests/test_fake_storage.py` (new)
`FakeStorage.objects: dict[bucket, dict[path, {"data": bytes, "content_type": str}]]`. `from_(bucket)` returns a bucket with these methods. `upload(path, file, file_options)` raises `FakeStorageError` if the path exists and `upsert` != `"true"`. `create_signed_url(path, expires_in)` returns `{"signedURL": f"https://fake.storage/clips/{path}?token=fake&expires={expires_in}"}` and raises on a missing path. `remove(paths)` deletes the paths and ignores missing ones. There is no `get_public_url`.
- **Test first:** upload stores bytes + content type; a second upload at the same path with upsert "false" raises; signed URL contains the path and `expires`; signing a missing path raises; remove deletes it. **Depends on:** none · **Size:** ~90
